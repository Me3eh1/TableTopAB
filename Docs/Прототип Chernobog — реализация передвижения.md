# Прототип Chernobog — реализация системы передвижения

Статус: **прототип реализован и проверен автотестами** (10/10, PIE-батарея от 2026-10-16).
Коммит: `3a5ea57`. Движок: Unreal Engine 5.8.

Исходные требования: [`Docs/Прототип Chernobog.md`](./Прототип%20Chernobog.md), разделы 2–7.
Разделы 8 (боёвка) и 9 (анимации/камера) покрыты интеграционными хуками, полноценные системы — следующий этап.

---

## 1. Сводка

Прототип от первого лица на C++-ядре (`ACharacter` + кастомный `UCharacterMovementComponent`) с Blueprint-обёртками. Реализовано:

- Обычное движение 7 м/с с практически мгновенной остановкой (§3.1)
- Защитная стойка: ×0.5 скорости, расход выносливости, riposte-хук (§3.2)
- Уклонение: импульс 13 м/с, фиксированная траектория, лимит серии, кулдаун, стоимость стамины, проход сквозь противников, остановка стеной (§3.3)
- Прыжок 7 м/с, падение, приземление, воздушное уклонение (§3.4)
- Трёхслойные состояния: вертикаль / локомоция / бой (§5)
- Приоритеты команд: оглушение > уклонение > прыжок (§5)
- Матрица коллизий: уровень блокирует всегда, враги блокируют ходьбу, но не уклонение, союзники не блокируют (§7)
- Все параметры редактируются в Blueprint без пересборки (§4)

## 2. Управление (§2)

| Команда | Действие | Input Action |
| --- | --- | --- |
| W/S | Наземное перемещение вперёд/назад | `IA_MoveForward` (Axis1D, S — модификатор Negate) |
| A/D | Наземное перемещение влево/вправо | `IA_MoveRight` (Axis1D, A — модификатор Negate) |
| Мышь | Обзор | `IA_Look` (Axis2D, Mouse2D; инверсия питча — в C++) |
| Space | Прыжок | `IA_Jump` |
| Ctrl | Уклонение (по направлению ввода, иначе по взгляду) | `IA_Dodge` |
| ПКМ (удержание) | Защитная стойка | `IA_Guard` |
| ЛКМ | Атака (заглушка; из стойки — riposte) | `IA_Attack` |

Контекст: `IMC_Default` (`/Game/Input/IMC_Default`), приоритет 0, добавляется персонажем в `NotifyControllerChanged`.

## 5. Приоритеты и правила (§5)

1. **Stunned** (`SetStunned(Duration)`) — полностью режет ввод, прерывает стойку и уклонение, обнуляет скорость.
2. **Уклонение** прерывает обычное движение и стойку; доступно в падении (одно воздушное до приземления); прерывание атаки уклонением — за боевой системой (флаг в состоянии `Attacking` будущего этапа).
3. **Прыжок** — только с опоры.
4. Невалидные команды (кулдаун, лимит серии, нет выносливости) игнорируются молча, без некорректных состояний.

Направление уклонения: живой вектор ввода в момент нажатия (`CMC->GetLastInputVector()` — то, что потреблено в прошлом тике; диагональ при зажатых W+D — штатно по §3.3); при отсутствии ввода — направление взгляда. Кэширование ввода в обработчике `ETriggerEvent::Triggered` не используется: на отпускании клавиши приходит только `Completed`, и закэшированное значение «зависало» — уклонения улетали по диагонали (исправлено 2026-10-16).

## 6. Уклонение — детали реализации

Кастомный режим `MOVE_Custom / CMOVE_Dodge` в `UTableTopCharacterMovement`:

- Скорость по профилю: линейная интерполяция от `DodgeStartSpeed` (= импульс × коэффициент направления) до `DodgeEndSpeed` за `DodgeDuration`. Ускорение от ввода равно нулю — траектория фиксирована (§3.3).
- **Стена останавливает уклонение**: если нормаль блокирующего удара противодействует направлению уклонения сильнее `DodgeWallStopDot` (0.3), уклонение завершается со скоростью 0 — фактическая дистанция выходит меньше расчётной (§3.3, §7). Скользящие касания проскальзывают вдоль поверхности.
- **Проход сквозь противников**: на время уклонения капсула переключает ответ канала Pawn → Ignore, после — Block (§3.3, §7).
- **Воздушное уклонение**: гравитация сохраняется, вертикальная скорость продолжается с момента активации; приземление возвращает в наземную физику и досуха отыгрывает оставшееся время уклонения.
- Прижим к опоре на пандусах/ступенях через `FindFloor` + snap вниз на каждом тике.

## 7. Матрица коллизий (§7)

| Препятствие | Ходьба | Уклонение |
| --- | --- | --- |
| Геометрия уровня | блокирует (скольжение вдоль стен) | блокирует, останавливает уклонение |
| Противник (`DummyEnemy_*`, профиль Pawn) | блокирует | проход сквозь |
| Союзник (`DummyAlly_*`, Pawn + Ignore на канал Pawn) | проход сквозь | проход сквозь |

Правило движка: Ignore на любой из сторон отключает коллизию пары — отдельный канал союзников не понадобился. Открытый вопрос толпы (проталкивание, замедление) — за дизайном (§7, последний абзац доки).

## 8. Выносливость и стойка

`UTableTopStaminaComponent`: `TryConsume(Amount)` — атомарное списание (уклонение); `AbsorbGuardDamage(Damage)` — возвращает непоглощённый остаток урона (хук «стамина вместо здоровья», §3.2); события `OnStaminaChanged` / `OnStaminaDepleted`. При нуле выносливости стойка не активируется/спадает.

Стойка — производное состояние: активна, пока удерживается ПКМ + не уклонение + не оглушение + есть выносливость. Скорость пересчитывается автоматически при любом изменении условия.

### 8.1 HUD выносливости

`WBP_StaminaHUD` (`/Game/UI/`), родитель — C++ `UTableTopStaminaWidget`:
- Полоса + счётчик «75 / 100» внизу по центру экрана; обновление по событию `OnStaminaChanged`, без тик-поллинга.
- Зелёная — стамины хватает на уклонение, красная — не хватает.
- Раскладка задаётся в `NativeConstruct` (якоря/позиция/размер слотов): в ассете только два виджета `StaminaBar` / `StaminaText` на корневом канвасе.
- Подключение: `StaminaHUDClass` на `BP_TableTopCharacter`; виджет создаётся локально управляемому персонажу в BeginPlay.
- Текстовый отладочный HUD (`bShowDebugHud`) по умолчанию выключен; при необходимости включить на том же BP.

## 9. Отладка и автотесты

**Крутилка параметров (H)** — `UTableTopTuningMenuWidget`, панель справа, строится кодом (без ассета). Доступны живьём все параметры из §4 (движение, уклонение, выносливость, FOV) + кнопки: Reset к дефолтам BP, переключение дебаг-HUD, закрытие. Режим Game+UI: при открытом меню курсор виден, но WASD продолжает управлять персонажем — крутишь на бегу. Работает в PIE и в Development/Test-билдах; в Shipping биндинг ввода и создание виджета вырезаны (`#if !UE_BUILD_SHIPPING`). Новый параметр = одна строка-дескриптор в `UTableTopTuningMenuWidget::GetParams()` (`Source/TableTopAB/TableTopTuningMenuWidget.cpp`).

**HUD** (`bShowDebugHud`, по умолчанию выключен — см. §8.1): над персонажем — три слоя состояний, скорость, выносливость, кулдаун уклонения, счётчик серии, доступность воздушного уклонения.

**Правило процесса (с 2026-10-16)**: агент не запускает PIE и не гоняет автотесты сам — проверка вручную разработчиком по чек-листу ниже; батареи ниже — историческая фиксация первой валидации.

**QA-хуки** (BlueprintCallable, категория TableTop|Debug) — те же обработчики, что и реальный ввод:
`DebugMoveInput(Forward, Right)`, `DebugTriggerDodge()`, `DebugTriggerJump()`, `DebugGuardHeld(bool)`, `DebugTriggerAttack()`; на CMC — `StartDodge(Direction, Coef)`.

Батарея автотестов гонялась в PIE тик-драйвером через MCP (Python в редакторе): таймлайн ~18 с, состояние персонажа логировалось каждый слейт-тик. Результаты (2026-10-16):

| --- | --- | --- |

| 2 | Импульс уклонения 1300, стамина −25 | ✔ |
| 3 | Серия: 3-е уклонение в окне 0.9 с отклонено | стамина не списана ✔ |
| 4 | Стойка ×0.5 + регенерация | 350 см/с, GUARDED ✔ |
| 5 | Riposte из стойки | событие в логе ✔ |

Ограничение батареи: реальное нажатие клавиш через MCP недоступно (`APlayerController::InputKey` не экспонирован в Python), поэтому путь Enhanced Input → IMC → биндинги проверен косвенно (до тех же обработчиков) — см. ручной чек-лист.

### Ручной чек-лист (≈3 минуты, PIE в L_MovementArena)

1. Старт PIE без варнинга `WBP_StaminaHUD failed to compile`; полоса «100 / 100» внизу по центру, зелёная.
2. WASD — движение во все стороны, диагональ не быстрее прямой; отпускание — мгновенный стоп.
3. Мышь — обзор; при инверсии питча поправить знак `Input_Look` (`TableTopCharacter.cpp`).
4. Space — прыжок на платформы 1 и 1.2 м (платформа 2.5 м недостижима — так задумано).
5. Ctrl+W/A/S/D и Ctrl без ввода — уклонение по направлению/взгляду; два подряд — ок, третье в окне — нет; полоса стамины падает на 25 за дож, при <25 — красная.
6. Регрессия направления: зажать W+D, отпустить D (держать W), Ctrl — дож строго вперёд; без зажатых клавиш Ctrl — дож по взгляду; W+D зажаты — дож по диагонали (штатно).
7. Ctrl в прыжке при снижении — воздушное уклонение, одно до приземления.
8. ПКМ — стойка (скорость 350), ЛКМ в стойке — «Riposte triggered» в логе.
9. Ходьба в муляж-врага (цилиндры) — упор; уклонение сквозь него — проход; сферы-союзники — проход всегда.
10. Ctrl в упор в стену — уклонение гасится мгновенно.

## 10. Хуки для следующих систем (§8, §9)

- Боёвка: `OnRiposteTriggered`, `AbsorbGuardDamage`, `SetStunned`, `ECombatState::Attacking` + таблица «атака × движение» (§8) — точка расширения в `RefreshGuardState` / `TryStartDodge`.
- Анимации/камера: `OnStateChanged` для переходов и синхронизации с режимами; эффекты камеры — независимы от физики (параметры движения на CMC не трогают камеру).

## 11. Известные особенности окружения

- **Live Coding не подхватывает новые классы/функции** в этом проекте (патч линкуется, рефлексия не обновляется). Рабочий цикл изменений C++: закрыть редактор → `Build.bat TableTopABEditor Win64 Development -Project=...` (инкремент ~10 с) → запустить редактор.
- MCP-сервер (`127.0.0.1:8000`) живёт в процессе редактора: рестарт редактора инвалидирует сессию MCP-клиента — клиент должен переинициализироваться.
- Меша тела нет (вид от первого лица), анимаций нет — по скоупу прототипа.
- При старте редактора список MCP-инструментов может несколько минут быть неполным (VibeUE экспонирует инструменты после своей инициализации).
- **UMG через WidgetService**: виджеты, созданные с `is_variable=True`, генерируют BP-переменные с именами виджетов. Если у C++-родителя уже есть UPROPERTY с таким же именем — компиляция Widget BP падает («Internal Compiler Error: ... another object already exists»). Правило: члены C++ не называть как виджеты в WBP (поиск — `GetWidgetFromName("ИмяВиджета")`).
